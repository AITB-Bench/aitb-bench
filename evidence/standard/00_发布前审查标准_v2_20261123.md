# 00 · 发布前审查标准 v2（国际组织投稿 / 对外贡献专用）

生成日：2026-11-23　版本：v2（v1 见 `2026-10-29-10-32-29/w3c_strategic/30_发布前审查标准_2026-10-29.md`）
适用：W3C / IETF / ITU / ISO / Zenodo / 公告机构 的一切外发文本、代码、仓库贡献、邮件列表帖、公开数据集
本册性质：**流程标准 + 可执行判据**。每条判据都要么有脚本、要么有留痕模板；没有第 3 种状态。

---

## 零、一句话

参加国际组织的外发物，**不是"写得好"就能发，是"能被外人在自己的机器上重跑一遍"才能发**。

v2 相对 v1 的四处升级，全部来自 v1 之后踩到的真实教训：

| 升级 | 原因（实测） |
|---|---|
| 把 S7 的判据从"状态码 200"改成"**内容标记命中**" | 旧版与新版都返回 200；3000 字符的空壳页也返回 200 |
| 新增 **BLOCKED 状态** | EUR-Lex / legislation.gov.uk 对脚本裸访问返回 `202` 且空体；既不能当通过，也不能当失败 |
| 新增 **S9 GitHub 物件外人全量实测** | 私有仓匿名访问返回 404；仓库"存在"不等于"外人可核" |
| 把"伪绿"从 5 种扩到 **9 种** | 新增"202 当通过"与"以私仓冒充可核" |

## 一、S0–S9 十道判据

### S0 · 前提与范围（新增）

| 项 | 判据 | 留痕 |
|---|---|---|
| 事件真实 | 所依赖的公告 / 章程 / 归档可裸访问，且**有内容标记命中** | `link_direct_check` 输出 + 结果 JSON |
| 范围明确 | 这份材料主张什么、不主张什么，各一句写在正文开头 | 正文首段 |
| 对象固定 | 引用的协议 / 标准必须钉到**修订号**（`-03`，不是"最新版"） | 引用处写明修订号 |

**不许**：凭记忆引用"某组织的某文件"。

### S1 · 专家角色到位

| 项 | 判据 |
|---|---|
| 角色 | 至少一个明确的专业角色（法规 / 领域 / 标准化）审视**断言层**，不是润色 |
| 产出 | 该角色写下"哪条断言证据不足 + 缺哪份原文" |
| 不许 | 用"已自查"代替；用同一模型的多上下文冒充专家 |

### S2 · 流程四层留痕

L0 机读 → L1 人工逐段复读 → L2 红线逐条（禁写词 / 主体 / 授权）→ L3 明示授权（谁说"发"、发哪版、发到哪）。

**铁律**：L0 全绿 ≠ 可发。v1 已有此条，v2 再次写明，因为它是最高频的自我欺骗。

### S3 · 全面调研（覆盖不利证据）

| 检查点 | 判据 |
|---|---|
| 断言→一手源 | 每条对外断言可指到具体段落，不是"某组织说过" |
| 反方证据 | 至少两条**不利于我方**的已核事实，写进正文或附件 |
| 全集而非抽样 | 相关帖 / issue / 文件全部扫过；分母写出来（例："8 份归档中 14 次"） |
| 空白断言 | "没人做过"只能写成"在本线程记录里未见"，并给分母 |
| 竞品描述 | 对竞品的每一条技术描述，都要**按其原文核一遍**（v2 新增：本轮即抓出我方把 `not applicable` 误写成他人词表） |

### S4 · 红队测试（四视角 + 七路机器判据）

四视角：专家（"这条法条现在打开给我看"）／流程（"这句是哪个脚本证明的"）／红队（"哪句是编的"）／外人（"我有没有一个按钮可以按"）。

七路机器判据：身份 / 事实 / 引注 / 逻辑 / 口径 / 格式 / 攻击面。

**产出物**：一张"攻击清单"，每条给判定（打中／部分让步／可反驳），**必须至少有一条"打中并已改"**——一条都打不中，说明红队没做。

### S5 · 外人视角全量实跑（不带凭据）

| 物件 | 验法 | 通过标准 |
|---|---|---|
| 邮件列表帖 | 裸 GET 归档页 | 200 + **正文含关键句**（刚发出可能延迟渲染，标 BLOCKED-DELAY，隔时复验） |
| 官方站点 / 法条 | 裸 GET | 200 + 内容标记；返回 202/403 = **BLOCKED**，须人工浏览器复核并留副本 + 哈希 |
| 本地文件引用 | 路径解析 | MISSING = 0 |
| 单文件交付物 | 断网打开 | 无外部依赖（图片 base64 内嵌或本地相对路径） |

**不许**：用带 token 的成功证明外人能访问。

### S6 · 外部 AI 全量实跑（不可用子代理替代）

| 要求 | 判据 |
|---|---|
| 独立 | **非本方模型**；不得用同一模型的多个子代理冒充 |
| 输入 | 只给待发正文 + 一手源 URL，不给结论、不给分析稿 |
| 覆盖 | 全量，不许抽样章节 |
| 产出 | 逐句质疑清单，含"哪句无法核实" |
| 留痕 | 记录模型名、时间、提示词全文、逐条接受/驳回理由 |
| 诚实 | 它说"打不开"，就是没审，如实记录 |

**阻塞时的唯一正确动作**：在报告里写 `S6 = BLOCKED`，并写清阻塞原因与已备通道；**不得**把 S4 的成果记成 S6。

### S7 · 引用可直达（v2 判据重写）

| 检查 | 工具 | 通过线 |
|---|---|---|
| 裸访问可达 | `tools/link_direct_check.py` | 200 且 **must 片段命中** |
| 内容匹配 | 同上（must 数组） | 命中 1 条即可，但 must 必须是我方引用意图的那句 |
| 位置 | 人工 | URL 紧贴引用句，不作文末脚注 |
| 反爬 | 同上（`blocked_status`） | 记 BLOCKED，另附人工复核证据（副本 + SHA-256） |
| 签发 | 人工 | 每份外发物的链接清单单独存档（JSON），可复跑 |

**核心纪律**：**状态码不是证据，内容标记才是。** 这条是本册最贵的一条——为它付过一次假通过。

### S8 · 可视化到位（v2 加两条硬线）

| 检查点 | 通过标准 |
|---|---|
| 一图先行 | 结论先出图，正文极简 |
| 图能独立 | 遮住正文，只看图仍知道结论与关键数字 |
| 数字可回溯 | 图内每个数字能指到一个脚本或一份 JSON |
| 单文件交付 | 给人看的版本是一个断网可开的文件（图片内嵌） |
| 反向图表 | **必须有至少一张"对我不利"的图或标注**（例：期限图里画出"协议侧无载体"那一行） |
| 不许 | 多表格拼成"图"；装饰性占位 |

### S9 · GitHub 物件外人全量实测（新增）

我们提供的任何 GitHub 侧材料（仓库、文件、评论、release、数据集），必须从**外人角度**全量实测，而不是"我推上去了"。

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 匿名可达 | `python tools/github_visibility.py owner/repo`（**git 协议**：`git ls-remote` 无凭据列 refs 即 PUBLIC，报 auth/not-found 即 PRIVATE） | **不要用 REST 判**：匿名 `api.github.com` 对私有仓回 404、对限流回 403，两者混用会把公开误记成私有 |
| 快照等于本地 | 克隆后查本轮新增文件是否在 | 缺件即 FAIL ——"仓库公开" ≠ "外人能复跑本轮" |
| 文件可取 | `raw.githubusercontent.com/.../{commit}/path` | 200 + **该版本独有内容标记** |
| 双通道 | 再加 `cdn.jsdelivr.net/gh/...@{commit}/...` | 两条通道都命中同一标记（`@main` 会缓存旧版，禁用） |
| 可跑 | 干净目录 `git clone` → 按 README 一条命令跑通 | README 的命令**真能跑**，退出码 0 |
| 依赖 | 全新环境、不装私有包 | 无私有依赖、无硬编码本机路径 |
| 评论 | 匿名 API 读 `body` | 含关键句；页面 URL 可直接打开 |

**v2 新铁律**：**私有仓库对本线不算"已交付外人可核"。** 要么给公开快照，要么在报告里写 `S9 = FAIL(私有)`，并说明替代核验方式（例如把该轮结果以单文件 HTML 附在外发物里）。

## 二、九种伪绿（v2）

| 伪绿 | 症状 | 修法 |
|---|---|---|
| 清单式绿 | 只验我方自列的 URL 清单，缺失项从未进入检查 | 从正文反推应有项，与清单比对 |
| 自演式绿 | "外人实测"由本方模型扮演 | 标为自审，不计 S5 |
| 子代理式绿 | 同模型多上下文冒充外部 AI | 只算 S4，不算 S6 |
| 缓存式绿 | 推送成功 + 200 就判外人可见 | 内容标记 + commit 级 URL + 双通道 |
| **202 式绿**（新） | 官方站点返回 202/空体，被记作"可达" | 记 BLOCKED，附人工复核证据 |
| **私仓式绿**（新） | 私有仓推送成功，被记作"外人可核" | 匿名 404 即为 FAIL；给公开快照 |
| **自证式绿**（新） | 用自家脚本跑自家产物，声称"已通过外部测试" | 报告里必须写"本方机器跑出，不构成外部确认" |
| **403 式绿**（新） | 匿名 API 返回 403（限流）被记作"私有"或"已核" | 换 git 协议判可见性；403 ≠ 404 |
| **公开≠可跑**（新） | 仓库公开、clone 成功，就当"外人可复跑" | 必须查本轮产物是否在快照里；缺件即 FAIL |

## 二·补 · 防"假死"三条（AITB 运行纪律）

试真台跑一次审查要 60–120 秒，被人误读成"卡死"会直接毁掉信任。三条硬规矩：

| # | 规矩 | 实现 |
|---|---|---|
| 1 | **进度必须可旁观** | 每行同时写入 `runs/<id>/progress.log` 并 `flush`；`stdout` 接管道会缓冲到进程结束，那才是"假死"的真凶 |
| 2 | **单次运行有全局上限** | preset 的 `max_seconds`（默认 900）；超时的项记 **BLOCKED「未执行」**，绝不记 PASS |
| 3 | **闸门不依赖实时网络** | 网检（GitHub 可见性等）改为"**带日期的证据快照 + 时效上限**"（`evidence/*.json`，≤7 天）；网络抖动不能把闸门刷红，过期也不能自动变绿 |

对应的自检：任何人在跑之前先 `tail runs/<id>/progress.log`，能看到 `[START]` 就说明进程活着；看到 `[DONE]` 才是真结束。

## 四、执行顺序（每次外发照做，10 步）

```
1. 写稿（S0 范围三句先写）
2. 建链接清单 JSON → 跑 link_direct_check（最先，成本最低）
3. 断言→一手源表，含至少两条不利证据（S3）
4. 红队四视角 + 七路（S4），必须有一条"打中已改"
5. 出图（S8：一图先行 + 反向图 + 单文件）
6. 锚点自检（判定所依赖的每句原文可复现）
7. S9 GitHub：匿名 404/200 → 双通道 → 干净 clone 跑 README
8. S5 全量裸访问复跑（含 BLOCKED 的人工证据）
9. S6 外部 AI（阻塞则明示 BLOCKED，不得跳）
10. L1 复读 → L2 红线 → L3 授权（授权由用户本人给）
```

**第 2 步放最前**：缺链接越晚发现越贵，发出去不可修。

## 五、失败时的唯一正确动作

| 判据未过 | 唯一正确动作 |
|---|---|
| S7 链接 404 | 换通道或删引用；**不得**改成"见附件" |
| S7 BLOCKED（反爬） | 留人工复核副本 + 哈希，并在正文注明"机读受限" |
| S9 私有仓 | 打公开快照，或 REPORT 里写 FAIL |
| S6 无外部模型 | 写 BLOCKED + 已备通道；**不得**用子代理充数 |
| S8 只有表格 | 出真图；没有图就不发"给人看"的版本 |
