# 锚点自检报告（机械化，非人工判断）

生成：2026-11-23　｜　脚本：`锚点自检.py`　｜　被检对象：`draft-saihm-memory-protocol-03` 正文（本地副本 `../01_证据链/raw2/13_协议-03_正文.txt`，抽自 datatracker HTML）

## 一、这个工具解决什么问题

外人复跑包里最容易被质疑的不是判定，而是**"读取点"是不是我方编出来的**。人眼核对靠不住，所以把它机械化：每条判定声明依赖哪些原文片段，脚本回原文逐条查存在性，并对"本应不存在的词"做反向检查。

- 存在性检查：声明的锚点在指定节里是否真的出现（防编造字段名、编造公式）。
- 反向检查：声明"格式里没有某东西"时，该词是否确实不出现在该节（防把"我没找到"写成"不存在"）。
- 限定范围：每条检查只在自己引用的那一节里查，避免用别节的文字给本节作证。

## 三、自检过程中出现的一条实质修正：R5 必须拆成两行

查 §2.7 时读到原文，其中三句改变了 R5 的判法：

> "3. add the cellId to its **erasure list, a public, append-only set of erased cellIds** that matches the FORGET receipts in the audit log …, so that **any observer can rebuild it**. An operator MUST consult the erasure list on every saihm_recall and **MUST NOT return an erased cell to anyone**."
>
> "Each operator **MUST state in its published documentation which class it provides**, and MUST NOT describe access-control erasure as cryptographic. **Clients MUST NOT assert either class on the operator's behalf**."

结论：R5 原本一个"S"混装了两件不同性质的事。

- **删除已执行、且可被任何观察者独立重建**——比原判定更强：不仅有收据，还有公共只追加的删除列表，且回读时必须查列表、不得返回已删单元。这部分 **S**，读取点在 `erasure list` 与 FORGET 收据。
- **所声明的删除类别**——原文要求运营方"在其公开文档中声明"，**格式内没有类别字段，客户端甚至被禁止替运营方断言类别**。所以这一格的读取点在**协议之外**（运营方文档），按本表规则应记 **NS**，不能算进 S。

不拆的后果很具体：外部评审者只要引 §2.7 这一句，就能指出"你把文档级声明算成了格式面满足"。拆开后两行各自可核，攻击面消失。

## 五、这个工具不能证明什么（写清楚，免得被当成门禁）

1. 锚点存在 **≠** 判定正确。它只证明"我引的那句话在原文里"，不证明"由该句推得出这个判定"。
2. 只覆盖 §1.4、§2.1、§2.5、§2.7 四节；§2.2、§2.4、§4 的断言目前靠人工核对。
3. 反向检查是词面检查，同义词（如 `expiry`、`ttl`、`purge`）不会触发；若要更严，需给出同义词表。
4. 原文副本来自 datatracker HTML 抽文，若协议后续改版（-04），锚点须全部重跑。

## 六、它与人测的关系

- 机器自检：能证明"锚点不假"，**做不了**"判定是否成立"。
- 外人实测：能证明"另一个独立的人能不能复现"，**替代不了**机器自检的逐字核对。
- 两者都在，才谈得上"可复跑"。
