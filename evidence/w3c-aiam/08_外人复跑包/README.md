# 外人复跑包

目的：让**与本项目无关的人**独立重做那 7 行判定，用可运行的脚本比对，从而把"我们说的"变成"任何人照做都能得出的"。

这是发布前审查里"外人实测"那一门的工具，不是宣传材料。

## 文件

| 文件 | 用途 |
|---|---|
| `A_复跑任务包.md` | 给外部执行者：法规摘录 + 协议锚点面 + 7 个义务，**不含我们的判定** |
| `B_核对任务包.md` | 给另一组或已完成 A 的人：我们的 7 行 + 5 个"请重点攻击"的点 + 4 个总体问题 |
| `结果模板.json` | 提交格式 |
| `示例_参考.json` | 我们的判定（基准） |
| `示例_复跑.json` | 一份示例外部结果（用于自检脚本，不是真实复跑） |
| `复跑评分.py` | 比对脚本，输出一致率与重点分歧，写入 `比对报告.md` |
| `比对报告.md` | 脚本生成的报告 |
| `锚点自检.py` | **机械化核对**：每条判定引用的原文锚点回 -03 正文查存在性 + 反向查"本应不存在"的字段 |
| `锚点自检报告.md` | 自检结果与它抓出的我方错误（首跑 5/7，修引用后 25/25），含 R5 必须拆行的结论 |
| `锚点自检_输出.txt` | 最近一次运行原始输出 |

## 怎么跑

```powershell
cd 08_外人复跑包
python 锚点自检.py                                   # 先查锚点是否真实存在
python 复跑评分.py                                  # 自检：用两份示例跑一遍
python 复跑评分.py 示例_参考.json 结果_张三.json      # 实际比对
```

顺序不能反：锚点自检不过，复跑就没有意义——那是拿编造的读取点去考别人。

自检的预期结果是**不通过**（一致率 5/7，关键行 O2、O4 分歧）。这是刻意的：如果示例能"通过"，说明评分器是个橡皮章。

## 验收规则

通过需同时满足三条：

1. 一致率 ≥ 5/7；
2. 无"缺口被判成满足"（参考为 `NA`/`NS` 而对方判 `S`）——这类错误会让读者以为义务已履行；
3. **关键行无分歧**：O1 期限载体、O2 原值取得、O4 授权归属、O7 删除边界。这四行决定整份提案是"缺口清单"还是"已履行清单"。

## 怎么选执行者

- 至少两组：一组**没有任何项目背景**（最好是另一台独立 AI，只给 A 包和 -03 原文），一组**懂法规但不懂协议**。
- 明确告诉他们：看 `B` 就不是独立复跑。
- 记录：姓名或代号、日期、读的是哪一版协议、是否先看过 B。

## 结果怎么用

- 出现 `read_point_insufficient`：改读取点，不改判定。
- 出现 `disagree`：先判断谁对。若对方对，改判定并记进台账；若我们对，把理由写进该行，让下一位执行者能少走一次。
- 出现 `CRITICAL`：**整份提案停发**，直到该行被改清。
- 全部通过：这道门才算过，可进入 LGD-Eval 独立评审。

**该条已处理（2026-11-23）**：`04` 与 `04b` 的 R2 已改为 "S — no silent overwrite only"，并在备注里写死"does not assert that it survives to year seven"。现在这一格不再是隐患，而是提案里最诚实的一格。
